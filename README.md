# RaceGame — самообучающаяся гоночная машинка (NEAT)

Игрушечный симулятор гонок на pygame + pymunk, в котором машинка учится сама
проходить круг по трассе с помощью нейроэволюции (библиотека `neat-python`,
алгоритм NEAT — NeuroEvolution of Augmenting Topologies).

## Как это работает

- Машина бросает 7 лучей-сенсоров под углами `-150, -90, -45, 0, 45, 90, 150`
  градусов относительно своего курса и измеряет расстояние до ближайшей
  границы трассы по каждому лучу.
- Вместе со своим углом поворота, скоростью и "компасом" (углом на следующий
  чекпоинт) это даёт **10 входов** нейросети (все нормализованы примерно в
  диапазон `[-1, 1]` / `[0, 1]`).
- Нейросеть (обычная feedforward-сеть, топологию которой NEAT эволюционирует
  сама, начиная с 4 скрытых нейронов) выдаёт **2 выхода**: газ и руль.
- Одновременно симулируется целая популяция машин (по умолчанию 300 геномов,
  группами по 30), каждая — со своей нейросетью. Машины, которые едут дальше,
  проходят чекпоинты по порядку и завершают круги быстрее, получают больше
  fitness и с большей вероятностью "размножаются" в следующем поколении.
- Прогресс обучения (вся популяция целиком) сохраняется в
  `car_racer/checkpoints/checkpoints/*.pkl` после каждого поколения и
  подхватывается автоматически при следующем запуске.
- Все машины одной группы (по умолчанию 30) делят один общий `pymunk.Space` -
  физика шагает один раз на тик на всю группу, а не отдельно на каждую машину.
- Таймауты и время круга считаются по числу тиков симуляции (`TICK_RATE` в
  `car_racer/constants.py`), а не по `time.time()` - это не "плывёт" при
  снятом ограничении FPS (см. "Панель управления" ниже).
- Внизу окна обучения — панель со статистикой и кнопками: пауза,
  рестарт текущей группы, рестарт всего обучения (с подтверждением), выбор
  трассы на лету, и тумблер "Unlimited FPS" — при включении отрисовка
  полностью пропускается (не только снимается лимит FPS), и обучение идёт во
  много раз быстрее реального времени (на тестовой машине - в ~24 раза
  быстрее для группы из 30 машин).

## Структура проекта

```
car_racer/
  cars/
    abs_car.py        — абстрактный интерфейс машины
    physic_car.py      — машина на физике pymunk (используется в обучении)
    simplecar.py       — упрощённая кинематическая модель (ручной режим)
  screen/
    screen.py            — окно, отрисовка трассы/визуализация нейросети
    ui_panel.py           — нижняя панель: статистика + кнопки управления
  neat_runner/
    main.py             — основной цикл эволюции NEAT
    game_instatnse.py   — одна "игровая сессия" одного генома: decide()
                          (сенсоры/сеть/газ-руль) и resolve() (после общего
                          шага физики группы - столкновения/фитнес)
  runner/main.py         — ручное управление машиной (стрелки)
  tracks/
    points*.txt          — файлы трасс
    track_builder.py      — генератор трасс "по схеме" (прямые + повороты)
  config/config-feedforward.txt — конфиг топологии и мутаций NEAT
  file_manager/file_worker.py   — сохранение/загрузка чекпоинтов, парсинг трасс
  checkpoints/            — сохранённые поколения (*.pkl), в git не хранится
helpers/
  calculate.py            — геометрические утилиты
  draw_track.py           — конструктор трассы мышью (рисование + сохранение)
assets/                   — картинка машинки и т.п.
```

## Установка окружения

Нужен Python 3.11+ (разрабатывалось и проверено на 3.13).

**Windows / PowerShell — самый простой способ:**

```powershell
.\setup.ps1
```

Скрипт создаст `.venv` и поставит туда всё из `requirements.txt`.

**Вручную (любая ОС):**

```bash
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# Windows cmd:
.venv\Scripts\activate.bat
# Git Bash / Linux / macOS:
source .venv/Scripts/activate   # или .venv/bin/activate на Linux/macOS

pip install -r requirements.txt
```

После этого в PyCharm просто укажи `.venv` как интерпретатор проекта
(Settings → Python Interpreter), и всё должно запускаться из коробки.

> Все зависимости в `requirements.txt` — актуальные версии на момент
> написания (`pymunk 7.x`, `neat-python 2.0`). У обеих были breaking changes
> в новых мажорных релизах; они проверены вручную и не задевают этот проект,
> кроме конфига NEAT — в `config-feedforward.txt` под них уже внесены два
> исправления (добавлен обязательный `no_fitness_termination`,
> `activation_options` приведён в соответствие с `activation_default`).
> Старые чекпоинты обучения удалены, так как несовместимы с neat-python 2.0.
> Подробности — в комментариях `requirements.txt`.

## Запуск

Все команды выполняются **из корня репозитория** (код использует
относительные пути вроде `./assets/car.png`), через флаг `-m`:

```bash
# Обучение NEAT — основной режим. Продолжает с последнего чекпоинта,
# если он есть в car_racer/checkpoints/checkpoints, иначе стартует с нуля.
python -m car_racer.neat_runner.main

# Ручное управление одной машиной (стрелки на клавиатуре)
python -m car_racer.runner.main

# Конструктор трассы мышью: рисуешь линии, "Сохранить" фиксирует линию,
# "Закончить" сохраняет файл в car_racer/tracks/
python -m helpers.draw_track

# Генератор трассы по схеме (прямые/повороты вместо рисования мышью) —
# создаёт готовые примеры треков в car_racer/tracks/
python -m car_racer.tracks.track_builder
```

Чтобы запустить обучение или ручной режим на другой трассе, передай имя файла
в `Screen(track_file="points_oval.txt")` (по умолчанию используется
`points.txt`).

## Формат файла трассы

Текстовый файл в `car_racer/tracks/`, который читает
`file_manager.file_worker.parse_track`:

1. строка — внешняя граница трассы, список точек `[[x, y], ...]`
2. строка — внутренняя граница трассы, тот же формат
3. …N-1 строк — чекпоинты, каждый как пара точек `[[x1,y1],[x2,y2]]`
   (отрезок поперёк трассы; проходятся строго по порядку)
4. последняя строка — линия старта/финиша, тот же формат пары точек

## Известные особенности

- `car_racer/checkpoints/` быстро разрастается (каждый чекпоинт — вся
  популяция NEAT целиком через `pickle`, счёт может идти на сотни МБ —
  гигабайты за пару сотен поколений). В git не коммитится; если не жалко
  прогресса обучения, старые файлы можно смело удалять — на следующий
  запуск это не влияет, кроме того что обучение начнётся с чистой популяции.
- `PhyCar` и `SimpleCar` во многом дублируют друг друга (сенсоры, проверка
  столкновений) — это осознанный технический долг, а не забытая копипаста.
- Сенсоры считают пересечение лучей со стенами трассы вручную через numpy
  (`helpers.calculate.cast_ray`), без `shapely` — это было самым дорогим
  местом в тике обучения (создание Python-объектов геометрии на каждый
  сегмент трассы на каждый луч на каждую машину). `shapely` больше не
  зависимость проекта.
